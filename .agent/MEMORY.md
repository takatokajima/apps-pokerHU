## CPUについて
- ユーザー希望は「ダミーCPUで盛り上がって見せたい」
- 実装は「CPU」と明示した練習相手（ランク待ち20秒後に提案、レート変動なし）。オンライン人数は水増ししない
  - 理由: 人間と偽ると信頼・景品表示/規約面のリスク。変更する場合はユーザーと再相談

## ログイン後UIをTen-Four風に（2026-09-25 第6弾）
- 共通レイアウト AppShell: ヘッダー（ロゴ・通知ベル・メニュー）+ PCは左ナビ / スマホは下部タブ（Home / Stats / Leaderboard / Hand History）
- ロゴは本作オリジナル（金のスペード + HEADS-UP）。Ten-Fourのロゴは真似しない
- メニュー: 名前・User ID・アカウント・設定・このアプリについて・よくある質問・アップデート情報・利用規約
- アップデート情報は src/client/lib/updates.ts に追記（先頭が最新、未読はベルに緑の点）
- 試合終了画面 = Ten-Fourの離席中画面の構成（この試合のハンド数・時間・実収支・EV収支 + もう一度/Hand History/ホームへ）
- Stats は期間（今週/今月/直近Nハンド/All）で成績を再計算。サーバーは1ハンドごとの要約(hands)を返す
- Hand History は直近100ハンド、Preflop/Postflop・SRP/3BP+ 絞り込み、ブックマークは端末のブラウザに保存
- アイコンは lucide-react

## CPU名称とKINGの見直し（2026-09-25 第7弾）
- 表示名: strong=KING / normal=QUEEN / weak=JACK（日本語表示でも英語）。内部の値（strong/normal/weak）は据え置き
- KING（GTO寄り）の考え方:
  - プリフロップ: SB 約85%オープン、BB 約75%ディフェンス（3ベット約15%）、15BB以下はプッシュ/フォールド
  - Cベット 約70%（フロップ1/3ポット）、ターン2発目は約50%（ドローのセミブラフ込み）、リバーはバリュー＋理論比率 s/(1+2s) のブラフ
  - ベットされたら「相手のベット範囲（頻度×バリュー/ブラフ比率で想定）」への勝率 × 実現度（OOP 0.8 / IP 0.95、役も伸びしろもない手はさらに0.8倍）がポットオッズ以上 かつ MDF の範囲内ならコール
  - チェックレイズ: 上位10%のバリュー＋ドローのセミブラフ
- 計測（1500ハンド, KING同士）: Cベット73% / Cベットへのフォールド26% / レイズ11% / BBディフェンス74% / 3ベット15%
- 対戦（150試合）: KING vs JACK 83%、KING vs QUEEN 59%

## デプロイ方針（2026-09-25）
- Vercel は常時接続のサーバー（Socket.IO）を置けないため、Vercel 版は「オフライン版」: CPU戦をブラウザ内（src/client/lib/localServer.ts）で完結
- Vercel のビルドでは VERCEL=1 → vite の define で __OFFLINE__=true。ローカル dev / Render はサーバー版のまま（OFFLINE=1 で手動切替も可）
- オフライン版: ランクマ・フレンド・ランキングは「準備中」表示。成績・ハンド履歴・プロフィールは localStorage（直近150ハンド）
- 対人戦を公開するときは、ゲームサーバーを Render 等に置く（render.yaml あり）か、Supabase Realtime 等に作り替える
- スターティングハンドの順位表は src/shared/handRanks.json（再生成: npx tsx scripts/make-hand-ranks.ts）
- Vercel プロジェクト名 pokerapps（アカウント takatokajima-2097）。本番URL https://pokerapps.vercel.app 、デプロイは `vercel --prod --yes`

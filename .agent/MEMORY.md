# プロジェクト知識

## 決定事項（2026-09-25）
- ヘッズアップのみ。モードはランクマッチ／フレンドマッチ（合言葉、レートなし）
- 持ち点50,000、5分ごとにブラインド2倍、Lv1 = 100-200 (BBアンテ200)
- 持ち時間15秒 + タイムバンク30秒×5回（連続使用可）
- 切断中は自動チェック/フォールド、3分戻らなければ負け
- レート: Elo(K=60) → 同レート±30。初期1500
- アクト90日。新アクト: 1000下げる（1500未満にはしない。元々1500未満ならそのまま）、上限7000
  - ユーザーは将来ランク帯の導入も検討中
- ゲストもランクマ参加可、ランキング非掲載。アカウント化（Supabase匿名→連携）で同じIDのまま引き継ぎ
- ランキングTOP1000（今アクトで1戦以上の登録ユーザー）
- 日本語・英語対応。お金を賭ける要素は一切なし。収益化は将来（スタミナ or 広告）
- 想定同時接続3000人

## CPUについて
- ユーザー希望は「ダミーCPUで盛り上がって見せたい」
- 実装は「CPU」と明示した練習相手（ランク待ち20秒後に提案、レート変動なし）。オンライン人数は水増ししない
  - 理由: 人間と偽ると信頼・景品表示/規約面のリスク。変更する場合はユーザーと再相談

## 技術メモ
- Windows の preview は PORT 環境変数を上書きするため、dev サーバーは `--dev` で 3001 固定
- `.env*` は権限設定で読めない/編集できない（.env.example の ACT_EPOCH は 2026-10-01 のまま、コードの既定値は 2026-09-01）

## UI改修（2026-09-25 第2弾）
- タイムバンクは手動（+30秒ボタン、5回）。時間切れ → チェックできればチェック、できなければフォールド
- ベット終了後 1秒の「間」を入れてから次のカード（エンジンの transition フェーズ）
- オールイン時は勝率（ボード3枚以上は全通り計算、プリフロップは2万回サンプリング）とアウツ（負けている側の次の1枚の逆転枚数）
- 設定画面: BB表示 / レイズ倍率(×) / ベット額(ポット%) / 言語（端末のブラウザに保存）
- デザイン: 暗いグリーン基調、Outfit + Zen Kaku Gothic New（セリフ体・筆記体は不採用＝ユーザーが「ださい」と判断）

## Ten-Four参考の改修（2026-09-25 第3弾・ブランチ feature/tenfour-ideas）
- 採用: 1,2,3,4,5,6,9,12,13,14,15,16,20,21,22（23=ログイン方法は現状維持）。比較表は docs/planning/tenfour-comparison.md
- 不採用: 7(直近ハンド収支バー) 8(SPR) 10(BB表示を初期値に) 11(離席) 17(ランク帯) 18(2卓同時) 19(Fast Fold)
- 成績はCPU戦を除いて集計（ハンド履歴自体はCPU戦も保存）
- エンジンに invested(投資額) と log(スナップショット付きアクションログ) を追加。ハンド記録・リプレイ・アクションログの元データ
- オールインEV = オールイン確定時の勝率 × ポット − 投資額
- 利用規約/プライバシーポリシーは【運営者名】【連絡先】【制定日】が空欄のまま。公開前に要記入・要確認
- 今週ランキングは月曜0時(JST)起点、ランクマの勝利数
- PWA: manifest + sw.js（本番ビルドのみ登録）。内蔵ブラウザではSW登録不可のため実機/HTTPSで要確認
